## Summary

Adds the Phase 1 user manual for staff managing the Ace Tours website,
plus the build system that produces the PDF.

- **Source content**: 3 intro chapters + 10 workflow chapters + 21 reference pages,
  all authored in Markdown under `docs/user-manual/` so a future in-app help drawer
  (Phase 2) can reuse the same content.
- **Build pipeline**: `scripts/build-user-manual.ts` reads `manual.config.json`,
  concatenates chapters via `composeManual()`, and renders them through `md-to-pdf`
  with custom CSS. Run `npm run docs:manual:build` (or `:watch`).
- **PDF output**: 105 pages, A4, branded cover, role tags, callouts, page footers.
  Built artifacts live under `docs/user-manual/dist/` (gitignored); attach to a
  GitHub Release after merge.
- **Maintenance scaffolding**:
  - `STYLE.md` — voice, structure, callouts, frontmatter, role taxonomy
  - `README.md` — editing, building, capturing screenshots, releasing
  - `.github/PULL_REQUEST_TEMPLATE.md` — user-manual update checklist
  - Stale-content warning in the build script (6-month threshold on `last_updated`)

## Scope changes from the spec (worth knowing)

- The spec deferred 11 admin screens to Phase 2. In practice the manual covers
  **all 21 admin screens** in `reference/` — Reconciliation, Fraud, Recovery,
  Reviews, Newsletter, Notifications, External services, Settings, Payments,
  Admin profile, and Staff/Users now have full reference pages, not stubs.
- The spec's conceptual roles `Owner / Operator / Admin` were partially replaced
  by the codebase's real roles `admin / field_service` (`shared/schema.ts`). Some
  chapters still list `owner`/`operator` and should be reconciled in v1.1 —
  documented in `docs/user-manual/README.md` → Known issues.

## Known limitations in v1.0.0

These are intentional deferrals to v1.1, documented in the manual's README:

- **No screenshots embedded.** The image-path rewriter is implemented and tested;
  PNG capture is the next pass.
- **Role taxonomy drift.** Some chapter frontmatter uses `owner`/`operator`
  alongside the canonical `admin`/`field_service`.
