## Summary

User manual v1.1.0. Three changes:

1. **Role taxonomy cleanup.** Eight reference chapters had `owner` or
   `operator` in their `roles:` frontmatter — names that do not exist in
   `shared/schema.ts`. Each was mapped to the canonical roles (`owner` →
   `admin`, `operator` → `field_service`) and deduplicated. One body
   sentence in `reference/staff-users.md` also rewritten. During execution
   the validator caught and the implementer fixed a ninth bad-roles
   header in `docs/user-manual/02-getting-started.md` that the original
   grep had missed.
2. **Build-script validation.** `scripts/build-user-manual.ts` now
   validates every chapter's `roles:` against `{admin, field_service,
   customer}` (matching `shared/schema.ts`) before composing the PDF.
   Unknown roles fail the build with exit code 1 and a clear error per
   file. Three new vitest tests cover the validator behaviour.
3. **Commercial-caution callouts** in seven chapters that touch
   revenue or paid-out money — pricing (workflow and reference),
   promotions, payments, reports (workflow and reference), external
   services. Identical "Confirm with the business owner or finance"
   text, rendered via the existing `caution` callout style.

A small build-pipeline improvement also landed alongside Task 3: the
markdown `> caution` blockquote syntax is now post-processed into
`<blockquote class="caution">` HTML so the CSS `::before` rule actually
applies the "CAUTION — " prefix. v1.0.0 advertised this styling but the
class wasn't being carried through to md-to-pdf — fixing it here keeps
v1.1.0 honest with its own STYLE.md.
